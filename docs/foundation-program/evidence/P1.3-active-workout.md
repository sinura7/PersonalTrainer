## Defects found by characterization

1. **Final-set rest race.** The ViewModel read the reactive set count after
   Room committed, then added one. A fast collector could count the new set
   twice and start rest after the last prescribed set. Counts are now
   snapshotted before the write.
2. **Hidden session-edit reasons.** Swap/remove caught
   `SessionEditRules` messages but filtered them through `SetLogRules`, so
   honest “already present” / “delete sets first” copy became generic.
3. **Cleared draft resurrection.** A late Room emission could repopulate
   cache/SavedState after finish or discard cleared them. A terminal gate and
   post-gate cache clear now close the race.
4. **Test timer side effects.** ViewModel tests used the Android controller,
   scheduling services/alarms and leaking Main work. `RestTimerGateway`
   separates the contract from Android delivery; production keeps
   `RestTimerController`, JVM behavior tests use an in-memory implementation.
5. **Fake teardown contention.** Tests now cancel-and-join ViewModel and
   DataStore scopes before resetting `Dispatchers.Main`.

## Known limitations

- Exact alarm delivery, stale alarm identity, and Doze are Phase 2; this
  journey proves the ViewModel-to-store handoff, not platform delivery.
- Notification-denied and large-text gym-floor variants remain P2.3/P9.
- P1.4 separately characterizes Start Options, Live Session Bar, Session
  Detail repair, and Workout Summary.
