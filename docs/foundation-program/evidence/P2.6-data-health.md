## Behavior contracts

**Empty ≠ unavailable:** an empty list is `Available`. A first read
failure is `Unavailable`. A later failure is `Degraded` and keeps the
last successful value, including a successful null.

**Copy:** History and settings fault copy never says "continue anyway"
or "reset".

**Onboarding:** unread settings failure is `UNAVAILABLE`, not `SETUP`.
A last successful `true` stays `APP`.

**Start / restore:** live-session read failure is refused
(`StartSessionOutcome.Unavailable`, restore `BackupException`).
Cancellation is rethrown, not wrapped as a data-health fault.

## Production change

`orLogAndFallback` is gone. Room/DataStore reads go through
`observeHealth`. History uses `observeHistoryHealth` and a Retry
fault. The setup flag is `onboardingCompleteHealth`. Start wrappers
catch read failures closed.

## Limitations

Catalog, routine, and schedule observes keep last values via
`presentValues()` and do not yet each own a dedicated fault screen.
History is the named FND-013 empty-masquerade surface. Home / Plan /
Library stay on their loading initial value when a first read never
emits, rather than rendering an empty catalog.
