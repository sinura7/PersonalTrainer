# P18 backup and restore

Labeled before the behavior is treated as done. The phone check stays later.

## A different heading for each stop

A wrong password, a file that is too big, a backup from a newer app, Drive with no connection, and settings that still need to be applied each get their own heading. The words under the heading are the message the operation already produced.

A live workout blocks restore with its own sentence: finish or discard that session first. A restore that landed the training data and still owes settings says so, and offers Finish restore.

## Success

The line that starts with Restored is written after the restore commit returns. A refusal does not use that line.

## One commit

Use this restore takes the pending plan once. The plan is cleared before the commit runs. A second tap has nothing left to commit. Back from the confirm drops the plan and writes nothing.
