**Do not put Room's *transaction* executor on the test dispatcher.**
Twenty-five `withTransaction` sites with suspending DAO calls inside,
several under a `Mutex`. It deadlocks, and deadlock presents as a hang — the
failure mode that already cost 5m39s to diagnose once.

**The structural finding that governs this work:** the old poll loops were
not only waiting. Each iteration called `advanceUntilIdle()` or
`runCurrent()`, so the loop was also *pumping the test scheduler*. Delete
one and a view model coroutine parked on a preferences read never resumes —
a test with nothing wrong with it hangs. That is why the `prefsDispatcher`
seam was the keystone rather than an extra. `TrainingInsightsSourceTest`
must never be converted this way: its share grace runs on the test scheduler
and its `assertSame` tests pass precisely because the polls never advance
virtual time.

Also owed: roughly ten files still polling, and moving the sixteen
source-reading policy tests into `tools/` checkers (nine already have a
Python twin there).

**Done when:** the remaining poll loops are gone, or each surviving bounded
wait carries a comment naming the boundary that forces it; count still 1650.

## 7. Constraints, and what is the owner's

1. **Never fix CI by weakening verification.**
   `gradle/verification-metadata.xml` is a hand-maintained SHA-256 ledger
   (619 components, 1110 artifacts) with `verify-metadata=true`. Do not turn
   that off, do not add blanket `<trust>` rules, do not loosen
   `tools/check-supply-chain.py`. Adding entries is fine: compute the
   checksum from bytes fetched twice, cross-check against Maven Central's
   published `.sha1`, insert in ASCII-lexicographic order with three-space
   indent and `origin="Generated by Gradle"`.
2. **Never skip, disable or quarantine a test to get green.** Every red run
   in this repository's history has turned out to be a real defect or a real
   barrier bug.
3. `tools/released-version-code.txt` is the gym-floor ratchet for
   `appVersionCode`. Writing a live-test number into it fails
   `tools/check-version-code.py`.
4. **Packet ownership.** Every packet has an Owns line. Editing another
   packet's file is a deviation and is recorded under *Floor findings*
   — newest first, bold paragraph, 76-character wrap, matching the existing
   entries.
5. Robolectric is pinned to **`sdk=35`**, not 36. Robolectric 4.16 maps API
   36 (Baklava) to required Java 21; this project is Java 17 everywhere.
   Enforced by `tools/check-sdk-target.py` and `SdkTargetTest.kt`. Raise it
   only together with the JDK.
6. Commit style is a sentence subject plus a body explaining *why*, with
   `file:line` references and the evidence. The history is the record this
   program relies on.

## 9. What the 2 September session established

CI had **never once passed** in this repository. `docs/DEVELOPMENT.md`
claimed no runner was assigned and that every run died before checkout.
False — and it is why nine consecutive red runs went unread. Every run was
dying 23–45 s in, on Gradle dependency verification. That document is
corrected.

Closing five ledger gaps let the build reach its tests for the first time,
and the first real runs found five defects that existed purely because
nothing had ever executed the thing that would name them:

1. The ledger gaps — guava-parent ×2, kotlinx-coroutines-bom, junit-bom ×2.
2. `robolectric.properties` pinned `sdk=36`, unsatisfiable on Java 17: all
   59 Robolectric classes failed identically at sandbox creation. A checker,
   a test and three documents all asserted `sdk=36` and were checking each
   other, never the lane.
3. **A shipped crash.** `InputStream.readNBytes` is API 33; `minSdk` is 26.
   Backup restore died with `NoSuchMethodError` on Android 8 through 12L,
   from a file and from Drive. It came from `96bceff`, which bounded the
   read on purpose to stop an OOM and reached for an API-33 method to do it.
   Replaced with `readAtMost` in `data/backup/BackupScaleBudget.kt`, pinned
   by `BoundedStreamReadTest` (seven cases, proved red-first), shipped as
   `debugLiveCode = 18` and confirmed by dex-inspecting the published APK.
4. `app/src/androidTest` uncompilable since `3a2a46f` — an import replaced
   rather than added — with no blocking job compiling it.
5. Two Compose `[ModifierParameter]` lint errors.

**Phase A** had been committed by an earlier session with *no executed
proof*: ten Robolectric tests never run, two Room `@Query` changes never
through KSP. All ten now pass and Room accepted both. Phase A is proved.

One correction worth carrying: a weekly-scheduling bug was briefly reported
as live on the phone. It was not. `OccurrenceGenerator` has no notion of
"now"; the test was racing a two-write publish in
`PlannerRepository.publishPinnedWeek`. That non-atomic publish is a real
seam and belongs to packet **C1**, recorded under *Floor findings*.

## 10. Failure modes this repository has already paid for

- **Raising a timeout to fix a hang.** The `eventually` helpers went 5 s to
  30 s on a slowness theory; the next run failed at 30 s in the same helper
  while the whole 1650-test suite ran in 59 s. A tight budget produces a
  slow pass, not a wait that never ends. Find what the code under test
  actually reads. Do not adjust a number.
- **Trusting a document over the machine.** "No runner assigned" survived
  nine red runs. When a document and a log disagree, the log wins.
- **Guards that check each other.** `sdk=36` was asserted by a checker, a
  test and three documents, none of which had ever run the lane. A gate that
  has never executed is not a gate.
- **Calling a flake fixed.** A green run does not retire a race, it records
  that the race did not fire. The suite is not deterministic until the
  `app/src/main` seams in §4 exist.
