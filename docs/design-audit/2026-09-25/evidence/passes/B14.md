### Notes on §2

**BR-1.** Provenance (C): `~/.gradle/caches/modules-2/files-2.1/io.ktor/ktor-client-core-jvm/2.3.12/…/ktor-client-core-jvm-2.3.12.module` declares `org.slf4j:slf4j-api` 1.7.36 and `kotlinx-coroutines-slf4j` for both `jvmApiElements` and `jvmRuntimeElements`; `ktor-client-android-jvm`, `-http-jvm`, `-io-jvm`, `-utils-jvm`, `-events-jvm` repeat it. The ledger carries `org.slf4j:slf4j-api` 1.7.36 (`gradle/verification-metadata.xml`). `slf4j-api` 1.7's `LoggerFactory.bind()` references `org.slf4j.impl.StaticLoggerBinder`, which no binding on the classpath provides; R8 treats a missing referenced class as fatal. The catalog gained `ktor-client-android` and `supabase-bom` in `0c759e7` (21 Sep, "Phase 11"); `proguard-rules.pro` was edited once since (`ba71dfd`, S0a, the `data.sync` keep) without a release build. Last recorded success: `docs/foundation-program/evidence/P12-field-operations.md:29-30`, pre-Phase 11. Counter-evidence looked for: (a) an slf4j rule — none in the 50-line file (`-dontwarn` only at :11-12,28); (b) a test pinning the release build — `SyncReleaseKeepRuleTest.kt:21` asserts the keep-rule text only, `check-play-rehearsal.py:46-49` greps `isMinifyEnabled = true`; (c) any lane running `assembleRelease` — only `release.yml:132` on `v*` tags, and origin has 0 `v*` tags (106 `debug-live-*`); (d) whether debug is hit — the debug block (`app/build.gradle.kts:135-147`) sets no `isMinifyEnabled`, so drops 99–104 built and shipped unshrunk, unaffected. After the rule lands, R8 may still break `gotrue-kt`/Ktor at runtime in a release build; that is moot while release builds ship no Supabase URL (`release.yml` never writes `supabase.properties`; `PRIVACY.md:46-47`), but B2's static R8 read should say so. Disposition (ADR-013): one quiet packet — add `-dontwarn org.slf4j.impl.StaticLoggerBinder` from `missing_rules.txt`, add `packages: ''` to `release.yml` (BR-2), and put an unsigned `assembleRelease` where it runs on every packet: the honest place under ADR-002 §5 is the local gate (`docs/HANDOFF-NEXT.md:121-125`), and ADR-024 also lets the deterministic hosted job carry it beside `assembleDebug` (`ci.yml:87-88`).

**BR-2.** The sibling workflows' own comments are the evidence (`debug-live.yml:58-62`: "Google no longer ships the obsolete `tools` package … which aborted live 59"; `ci.yml:49-51`). `release.yml` was written before that fix and has never run on a tag. Same packet as BR-1.

**DC-1.** Same section also still says "commit `<n>.json`" and the `2.json` note (`:495-501`) but not the byte-identical `app/src/debug/assets/` copy that `TemperSchemaAssetsTest` demands (`ADR-032 §4`, `HANDOFF-NEXT.md:16-21`). Disposition: the next docs pass (X7).

**BR-3.** `preflight.sh:138-141` bootstraps `build/test-jars` from the Gradle cache whenever it can, so on any machine that has run Gradle once the full preflight takes the domain-lane branch (`:250-252`) and fails; only a machine with no jars falls through to `./gradlew testDebugUnitTest` (`:253-255`) and passes. `verify.sh:38` also still says "re-run this script for FND-004" (closed 24 Aug). Disposition: tooling packet (X7): move the four files beside the tests they resemble (`test/ui/…`, `test/data/repository/…`) or make `run-domain-tests.sh` name test files individually as it already does for main sources (`:16-17`); then `tools/verify.sh` is honest again.
