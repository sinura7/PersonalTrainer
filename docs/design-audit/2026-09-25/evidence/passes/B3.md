### Notes on §2

**S-12.** Counter-evidence looked for: `data/backup/BackupJson.kt:30` calls `.serializeNulls()`, which
shows the omission is specific to the sync Gson, not a project-wide choice. `SyncPlanRemoteRowsTest.kt:30-50`
round-trips a `RoutineExerciseEntity` with `targetSeconds = null` and passes, because a *missing* key decodes
back to null; that test cannot see the omission. No `Prefer: missing=default` is sent, and it would not matter:
it governs the INSERT path, not `DO UPDATE SET`. PostgREST builds the `SET` list from the request body's keys
(its upsert documentation), so an absent key is left as stored. The phone that cleared the value is not
affected on its own pull: its local stamp equals the server's and `SyncRevision.remoteWins` needs strictly
greater (`domain/SyncRevision.kt:5-8`), so the two phones diverge silently and permanently. This also decides
S2a's design: an RPC with a `jsonb` parameter keeps explicit nulls, but only if the client sends them.

**S-11.** Counter-evidence: ids are UUID-suffixed (`ex-custom-<uuid>`, `goal-<kind>-<uuid>`), so a random
collision is negligible; the path needs the *same* id under two accounts, which every sign-in's
`bootstrapLocalSnapshot()` and restore-then-sign-in provide. `custom_exercise_muscles` already keys on
`(user_id, exercise_id, muscle_key)` (`packet-2:53`) and inserts fine for user B, so only the parent rows
fail. The `hasPendingChild` guards are pull-side; the push loop (`Engine:94-115`) marks the attempt and
rethrows, and `peekOutbox` returns the same row first next pass, so until S1's quarantine the block is
permanent. Server behaviour: user A's row is untouched, user B's copy is never stored, and B's pulls never
show A's row (SELECT policy), so B's phone believes the row was never uploaded. The fix is the packet-2
author's own pattern: `PRIMARY KEY (user_id, id)` on every table; PostgREST's `merge-duplicates` then
conflicts on both columns with no client change.

**S-13.** No clamp: `if (appliedAt > watermark) watermark = appliedAt` (`Engine:180`), and `nowMillis` is
used only for `sync_metadata`. `FakeSyncRemote.pullUpdatedSince` mirrors the server exactly
(`FakeSyncRemote.kt:30-38`), so the probe runs on the JVM. The only recovery today is a cursor reset, which
S-9/S1 add on sign-out. S2a's server-assigned change time (S-16) removes the mechanism, which is why this is a
rationale for S2a rather than new work; it is listed so the lead can weigh it, and may fold it into S-2.

**S-14.** Gate confirmed: `AccountSyncGate.kt:26`, read at `ui/settings/AccountCoordinator.kt:31,42`.
On the 8 defined tables the DELETE policy scopes the call (`packet-2:41-43,74-76,109-111`,
`packet-3:42-44,78-80,111-113,143-145,174-176`). A table missing from the server answers 404 and aborts the
sequence before the auth call, which is harmless. The exposure is only a table that exists *without* RLS,
which is exactly what S-8 says is unverified.

## Appendix B — policy review of the 8 defined tables

All 32 policies follow one template; line ranges in Appendix A.

| Question | Answer (C, from the two SQL files) |
|---|---|
| RLS enabled? | Yes on all 8 (`ALTER TABLE ... ENABLE ROW LEVEL SECURITY`). `FORCE ROW LEVEL SECURITY` is not set; that only affects the table owner, not the API roles. |
| SELECT | `FOR SELECT TO authenticated USING (user_id = auth.uid())` on all 8. |
| INSERT binds `user_id`? | Yes: `FOR INSERT TO authenticated WITH CHECK (user_id = auth.uid())` on all 8. A client sending another user's id is refused (403). |
| UPDATE has both clauses? | Yes: `USING (user_id = auth.uid()) WITH CHECK (user_id = auth.uid())` on all 8. A row cannot be moved to another user. |
| DELETE | `FOR DELETE TO authenticated USING (user_id = auth.uid())` on all 8. |
| `anon` excluded? | Yes: every policy is `TO authenticated`; with RLS on and no policy for `anon`, `anon` sees and writes nothing. `anon` still holds Supabase's default table GRANTs (`R`: `information_schema.role_table_grants`), which is safe only while RLS stays on. |
| `user_id` defaulted to `auth.uid()`? | No, nowhere. The client supplies it (`Rows`, every `toRemote(userId)`), and `WITH CHECK` enforces equality, which is equivalent in safety. S-16's trigger would set it server-side and make the client value irrelevant. |
| `SECURITY DEFINER` functions? | None. No functions at all. |
| Grants / revokes? | None in the files; Supabase defaults stand (`R`). |
| Table-to-table FKs? | None; only `user_id REFERENCES auth.users (id) ON DELETE CASCADE` (8 of 8). Deleting the auth user cascades every synced row. |
| CHECK constraints? | None; `status`, `kind`, `period`, `load_type` etc. are free `TEXT`. |
| Index for the pull? | `(user_id, updated_at_ms)` on all 8; with RLS adding `user_id = auth.uid()`, the pull's `updated_at_ms > X ORDER BY updated_at_ms` can use it. Redundant on the four `user_id`-keyed tables. |
| Upsert conflict target | PostgREST `merge-duplicates` uses the PK: `id` (tables 10, 13 — S-11), composite (11, 12), `user_id` (14-17). |

`get_advisors(type = "security")` and `get_advisors(type = "performance")`;

## Appendix D — S-16 in SQL (proposal for S2a; one table shown, the rest repeat)

```sql
CREATE SEQUENCE IF NOT EXISTS public.sync_change_seq;

CREATE OR REPLACE FUNCTION public.sync_stamp() RETURNS trigger
LANGUAGE plpgsql SET search_path = '' AS $$
BEGIN
    NEW.user_id := auth.uid();                                   -- ownership bound by the server
    NEW.server_seq := nextval('public.sync_change_seq');         -- total order for the pull cursor
    NEW.server_updated_at_ms := (extract(epoch FROM clock_timestamp()) * 1000)::bigint;
    RETURN NEW;
END $$;

ALTER TABLE public.custom_exercises
    ADD COLUMN IF NOT EXISTS server_seq BIGINT NOT NULL DEFAULT 0,
    ADD COLUMN IF NOT EXISTS server_updated_at_ms BIGINT NOT NULL DEFAULT 0;
CREATE INDEX IF NOT EXISTS custom_exercises_user_seq_idx ON public.custom_exercises (user_id, server_seq);
CREATE TRIGGER custom_exercises_stamp BEFORE INSERT OR UPDATE ON public.custom_exercises
    FOR EACH ROW EXECUTE FUNCTION public.sync_stamp();

-- Conditional upsert: an older write is refused, a tombstone wins a tie, nulls are honoured.
CREATE OR REPLACE FUNCTION public.sync_upsert_custom_exercises(rows jsonb)
RETURNS TABLE (id text, accepted boolean, server_seq bigint)
LANGUAGE plpgsql SECURITY INVOKER SET search_path = '' AS $$
DECLARE r record;
BEGIN
    FOR r IN SELECT * FROM jsonb_to_recordset(rows) AS x(
        id text, name text, muscle_group text, notes text, equipment text, load_type text,
        movement_key text, image_key text, name_key text, created_at_ms bigint,
        updated_at_ms bigint, deleted_at_ms bigint)
    LOOP
        INSERT INTO public.custom_exercises AS t (id, user_id, name, muscle_group, notes, equipment,
            load_type, movement_key, image_key, name_key, created_at_ms, updated_at_ms, deleted_at_ms)
        VALUES (r.id, auth.uid(), r.name, r.muscle_group, r.notes, r.equipment, r.load_type,
            r.movement_key, r.image_key, r.name_key, r.created_at_ms, r.updated_at_ms, r.deleted_at_ms)
        ON CONFLICT (user_id, id) DO UPDATE SET
            name = EXCLUDED.name, muscle_group = EXCLUDED.muscle_group, notes = EXCLUDED.notes,
            equipment = EXCLUDED.equipment, load_type = EXCLUDED.load_type,
            movement_key = EXCLUDED.movement_key, image_key = EXCLUDED.image_key,
            name_key = EXCLUDED.name_key, updated_at_ms = EXCLUDED.updated_at_ms,
            deleted_at_ms = EXCLUDED.deleted_at_ms
        WHERE EXCLUDED.updated_at_ms > t.updated_at_ms
           OR (EXCLUDED.updated_at_ms = t.updated_at_ms AND EXCLUDED.deleted_at_ms IS NOT NULL)
        RETURNING t.id, t.server_seq INTO id, server_seq;
        accepted := FOUND;
        IF NOT accepted THEN id := r.id; server_seq := NULL; END IF;
        RETURN NEXT;
    END LOOP;
END $$;
REVOKE ALL ON FUNCTION public.sync_upsert_custom_exercises(jsonb) FROM public, anon;
GRANT EXECUTE ON FUNCTION public.sync_upsert_custom_exercises(jsonb) TO authenticated;
```

Client side (S2b): pull with `server_seq=gt.X&order=server_seq.asc&limit=500`, cursor = last
`server_seq` (ties impossible); push through `POST /rest/v1/rpc/sync_upsert_<table>`; on `accepted =
false` drop the outbox row and let the pull deliver the winner; `serializeNulls()` on `syncGson`; keep
`revision` in the `WHERE` for `activity_sessions` (compare revision first, as ADR-031 §4 says). RLS still
applies inside the function (SECURITY INVOKER), so the policies in Appendix B remain the safety net.
