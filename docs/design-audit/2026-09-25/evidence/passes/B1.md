### Notes on §2

**S-11.** Counter-evidence looked for: any retry of skipped children (none; the cursor is the only pull state, `SyncEntities.kt:23-28`), any ordering guarantee on push (`peekOutbox` orders `createdAtMs ASC, id ASC`; `enqueue` stamps `nowMillis()` per row at `SyncOutboxWriter.kt:404`, and `enqueueCompletedSession` writes session, blocks and sets in one burst, `:26-58`, so ties are normal). `T/data/sync/SyncEngineTest.kt:246-274` and `SyncPullInPlaceTest.kt:285-296` pin the skip, not a later retry. The push-side stop is real: a failure at `SyncEngine.kt:109-111` after a child but before its parent leaves the child alone on the server until the next pass; whether the other phone runs a pass in that window is R.

**S-12.** Counter-evidence: no `TypeAdapter`, no-arg constructor or `@JvmField` on any `Remote*Row`; Gson uses `UnsafeAllocator` for these classes, so `revision: Long = 0L` defaults are skipped (primitive `long` lands as 0 anyway, which is why the defaults appear to work) and a missing `String` lands as null. `T/data/sync/SyncPlanRemoteRowsTest.kt` round-trips only complete JSON. Whether a live table can serve such a row is R (the 9 unpublished tables, S-8), but the engine's own `error()`/FK/DataStore throws share the path: `applyCoachRemote` with a null `availableEquipment` (`SyncAccountPrefs.kt:119`) fails the same way. `SyncCopy.ownerFacingError` turns the >120-char NPE message into the generic line (`SyncCopy.kt:38-39`).

**S-13.** Counter-evidence: no `serializeNulls()` (`SyncJson.kt:6`), no `Prefer: missing=default`, no `PATCH`/`PUT` path (`SupabaseRestClient.kt:14-30` is the only writer). The insert half is fine (absent key → column default). Activity blocks and sets are write-once snapshots (`ActivityRepository.kt:311-317`), so their nullable fields are not affected; routine lifts and schedule rules are edited in place and are. Accidental upside noted in §1 S-1 follow-up (c).

**S-14.** Counter-evidence: no stored enrolled id (ADR-031 §3 bullet 9 is not started), no user-id column on local rows to filter by, no cursor clear (`SyncDao.kt` has no `DELETE FROM sync_table_cursors`). The hooks are all-rows by design (`enqueueScheduleRules(userId, plannerDao.getRules())`, `SyncAuthoring.kt:56`). ADR-031 §4 assumes one owner; this needs two accounts on one phone, which the same ADR's sign-out bullet contemplates. `T/ui/settings/AccountCoordinatorTest.kt:111-178` pins only that `abandonOutboxOnSignOut` is called.
