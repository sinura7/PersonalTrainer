### Notes on §2

**UI-1.** Counter-evidence looked for: any other disarm on sign-out. `disarmAutoBackup` has two callers (`BackupCoordinator.kt:381` toggle off; `WorkoutSummaryViewModel.kt:197` when the Keystore blob will not open); `clearDriveSession` has one (`BackupService.kt:79`). No test under `app/src/test` mentions sign-out together with the sealed passphrase (grep `signOut` × `autoBackup|sealedPassphrase`: none). After sign-out the unattended upload declines consent (`WorkoutSummaryViewModel.kt:204-207,224`) and writes `AUTO_BACKUP_NEEDS_SIGN_IN`, which is what the "Paused — sign in to Drive again" subtitle (`BackupRestoreSection.kt:209-210`) is for — so the code treats sign-out as a pause, and PRIVACY.md:104 says delete. One of the two has to move; B5 owns the service, B14 the doc.

**UI-2.** What is announced is R; what is not present is C. The `Back` icon has `contentDescription = "Back"` (`ScreenHeader.kt:41,72`), so the likely experience is focus landing on "Back, button" with no title. Three heading styles as a visual matter are in §1; this row is the semantic gap only.

**UI-3.** `OnboardingApplier.kt:34-38` says a *finished* program is never deleted; `beginBlock` (`PreferencesRepository.kt:554-560`) says an abandoned block "is not" worth keeping and `:569` deletes it. `publishPinnedWeek` → `ensureWeek` (`PlannerRepository.kt:277-290`) only fills missing occurrences; that half is safe. The two `generateWeek` tests (`SettingsViewModelTest.kt:586,615`) pin inputs, not this.

**UI-4.** Adversarial: ADR-028 §4 only says "switch posture and open Account or Backup"; §2 says the chooser "does not repeat until the owner changes posture". Nothing binds posture to the session, so this may be classed as a target gap rather than a defect. Switching to ACCOUNT does the sensible thing (writes posture, opens the Account page: `SettingsScreen.kt:310-313`).

**UI-5.** `ReminderCopy.timeLabel` is spoken on the Row (`ReminderTimeWheel.kt:66-71`) so the *current* value is available. The gap is input. `SettingsHomeLayoutTest.kt:105-120` pins that the wheel exists (source text), not that it is operable.

## 4. Noticed, outside my scope

- **B5 (backup service):** `BackupService.signOut` (`data/repository/BackupService.kt:77-80`) does not disarm auto-backup — see UI-1; the fix sits in the service.
- **B3 (Plan):** `PreferencesRepository.beginBlock` (`:561-572`) deletes an unfinished current block; every re-run of guided setup and Settings' Generate a week goes through it (`OnboardingApplier.kt:102-108`). See UI-3.
- **B6 (rest timer):** changing "Default rest" in Settings writes prefs only (`SettingsViewModel.kt:465-469`); whether a running rest is affected is B6's; presets are 30/60/90/120/180 s + Custom (`domain/RestTimer.kt:86`; `RestPresetChips` `UI/components/RestTimerUi.kt:775-801`), custom validated by `RestTimer.parseCustom` (`:155-170`, 15 s–30 min, "90" or "1:30").
- **B7 (updater):** `DebugUpdateMonitor.kt:111-118` publishes `Idle` right after `installer.install(dest)` returns; no stalled/cancelled-sheet state exists for the banner to show (UI-20).
- **B8 (reminders/WorkManager):** `setReminderQuietHours` does not call `rebuildWorkoutAlarms()` (`SettingsViewModel.kt:268-274`) while opt-out and day alarms do (`:261-292`); that is fine only because quiet hours are applied at fire time (`data/repository/PlannerRepository.kt:431-459`, `domain/ReminderPolicy.kt:28-46`). Worth one test.
- **B11 (accessibility/design system):** `ScreenHeader`'s title has no heading semantics app-wide (`UI/components/ScreenHeader.kt:84-91`), `GymStatusBanner`/`GymErrorBanner`/`GymNoticeBanner` have no `liveRegion` (`GymStatus.kt:121-193,320-338`; only the undo host `:216-218` and the PR banner `:284-286` do), `SettingsStrip` uses `Role.Button` for exclusive choices (`SettingsChoice.kt:86-92`) — D08/F8a.
- **B12/B13 (sync/auth):** raw Supabase messages pass through `AccountAuthError.Message` (`SupabaseAccountAuth.kt:146`) — UI-16 is the visible half. `abandonOutboxOnSignOut` clears the outbox and `lastError` but not pull cursors (`SyncCoordinator.kt:41-50`) — S-9, S1.
- **B14 (docs truth):** `docs/PRIVACY.md:104` "signing out of Drive deletes that sealed copy" — contradicted by code (UI-1). `docs/PRIVACY.md:113` "Quiet hours are 22:00–07:00" — that is the default (`domain/SchedulePlannerModels.kt:117-118`) but the owner can set 20–23 / 5–8 in Settings (`domain/ReminderCopy.kt:26-27`; `ReminderPrefsSection.kt:169-203`; ADR-017 d6). `data/repository/prefs/SettingsStore.kt:22` and `BackupPrefsStore.kt:9` say "forty-six keys"; the file declares 55 (`SettingsStore.kt:76-139`) and `CURRENT_STRUCTURE.md` says 56. `LegalCopy.PRIVACY_POLICY_URL` (`domain/LegalCopy.kt:5-6`) points at `sinura7/PersonalTrainer/blob/trunk/docs/PRIVACY.md`, which matches the remote and the sitting branch; whether the repository is public enough for that link to open for a stranger is R (B13b can check).
- **B4 (first launch):** `SavePostureHost.kt:43-53` writes the posture and requests the Account/Backup sub-page through the shared Activity-scoped `SettingsViewModel` (`AppNav.kt:286,542-547` passes the same instance), so the hand-off is one object; nothing to add from my side.
