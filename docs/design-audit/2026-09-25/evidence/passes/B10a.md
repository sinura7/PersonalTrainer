### Notes on §2

**UI-1.** `weeklySeries` is `history.weeklyTonnage.map { it.bodyweightReps.toDouble() }` when `repsAreTheMeasure` (:128-134; `LoadClass.repsAreTheMeasure` is `this != LOADED`, `domain/LoadClass.kt:38`). The call passes `unit = unit` (:300) and `TrendCard` does:

```kotlin
headlineUnit = unit.suffix,                                   // :566
deltaLabel = seriesDelta(values, unit, grouped),              // :567 → "…$magnitude ${unit.suffix}" :646
contentDescription = trendDescription(title, values, pointNoun, unit, grouped), // :570 → "latest $latest ${unit.suffix}" :663
```

No branch on the measure exists inside `TrendCard`. Counter-evidence looked for: the all-time tile handles reps correctly (:249-253), which shows the intent; no test mentions "Weekly reps" or a bodyweight lift on this screen (`grep` over `app/src/test/.../ui/exercise` and `ui/history`: none). The hero above the chart therefore contradicts `SetCopy`'s own rule (`domain/SetCopy.kt:3-8`).

**UI-2.** `horizonProgress` (:188-229) is `combine(catalog, horizon, weightUnit) → key → distinctUntilChanged → flatMapLatest { flow { all(); emit(overRange(...)) } }`. The inner flow never emits a leading null (only when `key == null`, :214-217). `uiState` (:231-263) is `combine(catalog, visibleMonth, horizon, horizonProgress)`; `combine` re-runs on any source change with the others' last values, so the emission triggered by `horizon` carries the old progress. The screen prints `(progress?.recordsBroken ?: 0)` (:453) and `moved.exerciseName` (:472). `completed-training-convergence.md` §5 names `sessionsBetween(0, end)` as "the expected outlier", so the window grows with the log. Counter-evidence: `CompletedTrainingParityTest.kt:211-217` and `HistoryViewModelTest.kt:171-173` wait with `first { … > 0 }`, so they pass through the transient without pinning it; `ProductionScreensPassInstrumentedTest.kt:172-190` asserts only that the readout is displayed. The `HorizonTotals` half is computed synchronously in the same lambda (:254-259), so totals are never stale — the contract is broken only for PRs and mover, which sit in the same card under the same title.

**UI-17.** Which History reads are guarded and which are not, traced from `HistoryViewModel.catalog` (:142-180): guarded — `observeSessionSummariesHealth` (:145), `observeCompletedSummariesHealth` (:146), both `observeRecordSetsHealth` (:150-151); unguarded — `revision` (:112, :118, :147) and `all()` (:123, :218). `observeRevision` (`CompletedTrainingRepository.kt:219-231`) was written to key recomputes on activity completions, but it takes `activities.observeCompletedSummaries()` — the raw `mapLatest` over the DAO (`ActivityRepository.kt:120-124`) — rather than the `observeHealth` twin one function below (:126-127). `observeHealth` (`FlowGuards.kt:21-37`) is the only catch in the pipeline; nothing downstream has `.catch`. Counter-evidence looked for: the sidecar test `aSidecarReadFailureMarksThePageStaleInsteadOfVanishing` (`HistoryViewModelTest.kt:219`) and the parity case (`CompletedTrainingParityTest.kt:338`, `FailingObserveActivityRecordSetsDao`) both fail `observeCompletedStrengthSetRecords`, which is guarded; neither fails `observeCompletedSummaries` or `getAllGraphs`. My original §1 row read only the guarded branch; the coordinator's harness fails the unguarded one and never reaches a ready frame.

**UI-18.** `Text("History", modifier = Modifier.weight(1f), style = InstrumentType.display)` (:128-133) has no `maxLines`, and the `StartSheetOpener` (:134-137) takes its intrinsic width first; at font 2.0 the remaining width is narrower than the word, so Compose breaks it mid-word. The other tabs' headers are outside my scope (B-owners of Home/Body/Plan); Library uses `ScreenHeader` and renders whole at font 2.0 (`library/populated-360x640-font2.0.png` not reviewed; C from `ExerciseLibraryScreen.kt:96-101`, R for the frame).
