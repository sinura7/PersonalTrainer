### Notes on §2

**TS-1.** Counter-evidence looked for: `:app:staticChecks` (`build.gradle.kts:395-400`) runs `tools/preflight.sh` with `PT_STATIC_ONLY=1`, which `exit 0`s at `preflight.sh:246-249` before the JVM lane and never mentions coverage; `tasks.named("check") { dependsOn(staticChecks) }` adds nothing else; `ci.yml:76-98` runs `testDebugUnitTest`, `lintDebug`, `assembleDebug`, `assembleDebugAndroidTest`; the X5 commit message itself says "CI does not run it". The floors file's own rule ("Raise a floor when a packet adds tests", `coverage-floors.txt:129`) is already unmet: timer reads 81.7 % against a floor of 73 after W2b-2/W2b-3 added `timer/RestLockSkipTest.kt` (163 lines), `ui/workout/RestPageSkipTest.kt` (145) and 40 lines to `RestTimerControllerTest.kt` (`git diff --stat 28de703..HEAD`), which is why the lead's reading is 7 points above X5's 74.7 %. `isIncludeNoLocationClasses` is correct as configured: Robolectric's sandbox loader gives app classes no code source but does not rewrite their bytes (only framework classes are instrumented), so JaCoCo's class ids still match the on-disk classes that `jacocoTestReport` reads from `tmp/kotlin-classes/debug` (`build.gradle.kts:325-331`); X5's "same 3,346 classes … no class or method lost coverage" is the empirical check. `check-coverage.py:89-103` keys on the exact JaCoCo package name, and JaCoCo packages are flat, so `domain.coach` (892 instr, 85.4 %) and `data.repository.prefs` (3,907, 64.1 %) are *not* under the `domain` / `data.repository` floors; `ui.workout` has no subpackage, so its floor is whole.
